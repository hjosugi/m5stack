# StackChan音声版 — ロードマップ / 既知の制約（issue候補）

いま実装済みの機能は [README.md](README.md) を参照。ここは「むずかしい所」「今後やる所」を
issue代わりに残す。`gh issue create` で個別issue化してもよい。

## ハードウェア制約でむずかしい

- **声の方向に顔を向ける（音源方向）**
  CoreS3 のマイクは単一PDMマイク。到来方向推定(DoA)には最低2〜4chのマイクアレイが要る。
  → 現状は代替として「あたまをタッチした側へ顔を向ける」動きを実装済み
    （[StackchanVoice.ino](StackchanVoice/StackchanVoice.ino) の `g_listenGazeH`）。
  将来: PDM×2 or I2Sマイクアレイ増設 → GCC-PHAT等でDoA → 顔/視線を向ける。

- **カメラで手ふり・呼びかけに反応**
  GC0308 のSCCB(制御I2C)が内部I2Cと共有で、実機での初期化/ピン調整が要る。ブラインドでは危険。
  → `SCV_ENABLE_CAMERA=0` で保留（ガード済み）。まず単純なフレーム差分での「動き検知」から。
  呼びかけワード「スタックちゃん」は実装済みなので当面はそちらで代替。

## ソフトウェアの今後

- **ブラウザで設定できるGUI（`task gui`）**
  設定項目が増え、端末の吹き出し/パネルだけでは分かりづらい。
  案: PC側でローカルWeb UIを立て、各ファームの `.env` を編集・検証・書き出し。
  もしくは端末をWiFi APにして設定ページを出す。まずはPC側 `task gui`（FastAPIで.env編集）から。

- **`.ino` のリファクタ（モジュール分割）**
  単一ファイルが肥大。`avatar_ui / net / stt / llm / memory / personality` などに分割。
  機能は変えずファイル分割＋ヘッダ化。テスタビリティ向上。

- **感性・個性の高度化**
  現状はグローバルな `mood / energy / curiosity`（NVS保存、会話で更新、まれに自然変動）を
  表情と返事トーンに反映。次段階:
  - topicごとの「好き/きらい」affinityを学習（気に入る/気に入らないが個別に変わる）
  - 個性に応じて表情・台詞の**出現確率分布**を変える
  - まれに大きく性格が変わる“転機”イベント
  - 学習ログ（host `.local/memory/dsv-memory.jsonl`）を要約して個性へ反映

- **自己学習データの活用**
  host側に貯めた会話（`/memory`）を要約して端末へ還元、正規化質問のベクトル検索キャッシュ化。
