# 復旧とUSBトラブル対応

## まず切り分ける

USB列挙の失敗とファームウェア故障を混同しません。`error -71`やHubの再接続が見える場合は次の順で確認します。

1. データ通信対応USB-Cケーブルの差し直し・交換。
2. PCへ直結し、外付けHubや延長を外す。
3. 別のPC側USBポートを試す。
4. `task device:detect`でHubとESP32-S3が継続して見えるか確認する。
5. 安定後にだけポート権限、ブートローダー、Flashを調べる。

## Download Mode

[M5Stack公式StackChan文書](https://docs.m5stack.com/ja/StackChan)の手順では、ダウンロードモードへ入るにはResetボタンを約2秒押し、内部の緑LEDが点灯したら離します。

これは本体をリセットします。頭部と台座の周囲を空け、通常起動へ戻ったときのサーボ動作に備えてから行います。モーター部を手で無理に回してはいけません。Y軸の推奨範囲は5〜85度です。

## 全Flashバックアップからの復旧

バックアップ作成時と同じ実機を接続し、一時ACLを付けます。

```bash
task device:detect
./scripts/grant-port-access.sh
./scripts/restore-flash.sh --allow-flash \
  .local/backups/stackchan/<UTC時刻>/flash-16777216.bin
```

復旧スクリプトは次を確認してから全Flashを書き戻します。

- `.env`で固定したUSBシリアル、VID:PID、ポートが現在の実機と一致する。
- バックアップがリポジトリ内の`.local/backups/`にある。
- 保存済みSHA-256が一致する。
- ファイルサイズが選択製品のFlash容量と一致する。

書込み中はUSBと電源を抜かないでください。復旧後の再起動では手を離し、可動域外から確認します。

## バックアップがない場合

Flashを消去・上書きする前なら、何もせずバックアップを優先します。既に工場版を失い、バックアップもない場合は、公式のM5Burner/OTA配布状況と製品文書を確認します。公開StackChanソースは配布済み版より遅れる場合があるため、無条件の代替にはなりません。

## セキュリティ機能が有効な場合

Secure BootやFlash Encryptionが有効なら、読出せたrawイメージを一般的な復旧用バックアップとみなせません。このリポジトリのバックアップスクリプトは検出時に中止します。eFuse設定を変更したり、保護を解除しようとしてはいけません。
